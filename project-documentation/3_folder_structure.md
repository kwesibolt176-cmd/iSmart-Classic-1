# 3. Folder Structure

The project follows a standard React/Vite structure, heavily utilizing the `src` directory for frontend code and the `supabase` directory for backend configuration and edge functions.

## Root Directory

- `package.json`: Defines project dependencies, npm scripts, and metadata.
- `vite.config.ts`: Configuration for the Vite build tool. Handles plugins, path aliases (e.g., `@/` pointing to `src/`), and build optimization settings.
- `tailwind.config.ts`: Configuration for Tailwind CSS. Defines the custom design system, colors, animations, and typography used across the app.
- `components.json`: Configuration for `shadcn-ui`, specifying where generated components should be placed.
- `eslint.config.js`: Configuration for code linting to enforce code quality.

## `/src` (Frontend)

This directory contains all the React source code for the application.

- **`/assets`**: Static assets like images, icons, or global stylesheets (though most styling is done via Tailwind).
- **`/components`**: Reusable React components.
  - `/ui`: Contains low-level, highly reusable components primarily generated by `shadcn-ui` (e.g., Button, Input, Dialog, Select).
  - *(Root level of `/components`)*: Contains domain-specific, compound components (e.g., `LocationManagement.tsx`, `CustomerDetailsDisplay.tsx`).
- **`/contexts`**: React Context providers for global state management. Examples include `BusinessContext` (current active business) and `CartContext` (POS cart state).
- **`/hooks`**: Custom React hooks. These encapsulate complex logic and API interactions. 
  - e.g., `use-ismart-api.ts` for interacting with backend fintech endpoints.
  - e.g., `use-toast.ts` for triggering notifications.
- **`/integrations`**: Code related to third-party integrations.
  - `/supabase`: Contains the Supabase client initialization (`client.ts`) and TypeScript definitions generated from the database schema (`types.ts`).
- **`/lib`**: General utility functions and libraries.
  - `utils.ts`: Common helpers (e.g., merging Tailwind classes with `cn()`, formatting currency, formatting phone numbers).
- **`/pages`**: Top-level route components. Each file here generally corresponds to a specific URL route defined in `App.tsx` (e.g., `Utilities.tsx`, `Index.tsx`, `Wallet.tsx`).
- **`App.tsx`**: The main application component. It sets up the routing map, context providers, and global error boundaries.
- **`main.tsx`**: The entry point of the React application. It renders `App.tsx` into the DOM.
- **`index.css`**: Global CSS file. Includes Tailwind directives and base layer styles.

## `/supabase` (Backend)

This directory contains configuration and code intended to run on the Supabase platform.

- **`/functions`**: Supabase Edge Functions. Each subfolder represents a distinct serverless API endpoint.
  - `/_shared`: Contains reusable code shared across multiple Edge Functions. For example, `ismart-full-client.ts` and `ismart-financial-client.ts` which act as wrappers for external API communication.
  - `/ismart-utilities`, `/ismart-finance`, `/process-disbursement`, etc.: Specific edge functions that handle frontend requests, process logic securely, and return results.
- **`/migrations`**: SQL files that define the database schema, tables, relationships, and Row Level Security (RLS) policies. These are executed sequentially to build or update the PostgreSQL database.
- **`config.toml`**: Local Supabase CLI configuration file.
